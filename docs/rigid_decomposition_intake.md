# Native decomposition artifact intake

October 27, 2026 Main Edit source qualification. Ball owns collision assets and numerical motion; optiC consumes original visible geometry and immutable recorded poses. This is local development, separate from installed applications and release adoption.

`rigid_scene_native prepare-decomposition REQUEST NEW_DIRECTORY` imports an existing `ball_collision_representation_artifact_v1` compiler-output artifact. It does not invoke a decomposer, repair the STL or silently replace it with a hull. Ordinary `prepare` retains its closed-convex route, and `prepare-exact` retains its pinned bracket/arch reference route.

```json
{
  "schema": "ball_rigid_decomposition_request_v1",
  "asset_id": "channel",
  "source_path": "source.stl",
  "artifact_path": "compiler_output.bcr3d",
  "source_sha256": "<64 lowercase hexadecimal characters>",
  "artifact_sha256": "<64 lowercase hexadecimal characters>",
  "artifact_basis": "right_handed_y_up",
  "units": "meter",
  "scale": 1
}
```

Paths resolve relative to the request file, or may be absolute. All nine fields are required; unknown or duplicate fields refuse. `artifact_basis` accepts right-handed Y-up or Z-up. Source STL remains Z-up and unchanged. Legacy `(x,z,-y)` artifact coordinates are converted back to source Z-up by transforming the source mass frame; principal child geometry is retained.

Both input SHA-256 pins, closed connected source topology, producer accepted/compiler-output status and common-source/dynamic-compound capabilities are checked. Source volume, unit mass, density, COM, full central inertia and principal frame are independently checked against the STL. The normalized artifact retains producer source/settings/output identities and pins the original input artifact digest in its manifest field. Visible positions, triangles, IDs, bounds, pivot and topology metadata are checked again when loading. Preparation stages privately and publishes without replacement; an occupied output, malformed artifact or mismatch leaves no prepared output.

The admitted artifact envelope is 2–12 children, at most 64 vertices and 128 faces per child, unchanged 1 MiB file and source mesh budgets. Allocation declarations are bounded before entering the existing artifact reader. Native scenes and optiC's optional result metadata now allow 12 children per body, while the 32-body/496 child-pair and four-manifold budgets remain. Fast swept-response eligibility still has its separately qualified three-child limit. These capacities are not general CCD or many-body physical qualification.
